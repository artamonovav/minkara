# Архитектура

## Слои

```
scripts/*.py      CLI-этапы, тонкие: разбор аргументов + вызов библиотеки
src/minkara/      переиспользуемая логика, без побочных эффектов при импорте
config/           декларативные настройки (модели, шаблон env)
data/ out/ work/  runtime-каталоги, в git не попадают
```

## Модули

### `config.py`

`load_settings()` собирает `Settings` из переменных окружения и путей
репозитория, создаёт runtime-каталоги. `load_models()` читает
`config/models.yaml`.

Пути:

| Каталог | Назначение | В git |
|---|---|---|
| `data/raw/` | сырой HTML, разложенный по URL | нет |
| `data/assets/` | картинки и прочие файлы | нет |
| `data/archive.sqlite` | состояние пайплайна | нет |
| `out/site/` | собранный офлайн-сайт | нет |
| `work/` | временные файлы, черновики | нет |

### `urls.py`

* `canonical()` — приводит URL к виду `https://host/path?<только нужные
  параметры>`: убирает фрагмент, `ct`/utm-метки, сортирует параметры.
  Нужно, чтобы одна и та же страница не попадала в БД дважды.
* `classify()` — определяет `kind` (`listing`, `note`, `parts`, `asset`,
  `other`) и извлекает `model/section/uid/car/note`.
* `raw_relpath()` — куда положить HTML: повторяет структуру URL
  (`userid/2025950/car/2972657/6379447/note.html`).
* `asset_relpath()` — куда положить картинку: сохраняет путь на CDN,
  отбрасывает query-строку.

### `http.py`

`Fetcher` — обёртка над `requests.Session`:

* ограничение частоты (`MINKARA_DELAY`, по умолчанию 1 с);
* повторы с экспоненциальной паузой на 429/5xx и сетевых ошибках;
* `Retry-After` учитывается;
* `403` → `BlockedError` с подсказкой про VPN (не ретраится);
* один и тот же User-Agent и `Accept-Language: ja` для всех запросов.

### `parse.py`

Чистые функции `html -> dict`, без сети и БД:

* `parse_listing()` — элементы списка: URL, заголовок, лид, дата, автор,
  лайки/комментарии, миниатюры, сложность;
* `parse_note()` — шапка заметки + галерея (`galleryTitle`/`galleryPhoto`/
  `galleryMemo`), соседние заметки, счётчик лайков;
* `parse_parts()` — отзыв о товаре (оценка, текст, фото, категории);
* `extract_text_units()` — какие строки пойдут в перевод.

Парсеры опираются на устойчивые признаки (id с суффиксом `_HL_Image`,
классы `galleryMemo` и т.п.), а не на порядок элементов.

### `db.py`

`Store` — тонкая обёртка над SQLite (WAL). Схема и инварианты:

* `pages.url` уникален; состояние меняется `new → fetched → parsed`
  (или `error`);
* `assets.url` уникален; привязка к странице через `page_url`;
* `text_units` уникальны по `(page_id, kind, idx)`; перевод кэшируется по
  `hash` исходного текста.

## Поток данных

1. `01_discover` читает листинги, пишет `pages` (kind=listing/note).
2. `02_fetch` берёт `pages` со `state=new`, сохраняет HTML в `data/raw`,
   парсит, складывает метаданные в `meta_json`, регистрирует картинки в
   `assets`; затем качает `assets` со `state=new`.
3. `03_translate` наполняет `text_units` из `meta_json` и переводит те, у
   которых пусто `ru`.
4. `04_build` читает `pages`/`text_units` и генерирует `out/site`.

## Ошибки и повторные запуски

* Все этапы можно прерывать Ctrl-C: состояние фиксируется постранично.
* Повторный запуск докачивает только `state=new`/`error`.
* `--limit` ограничивает число обрабатываемых объектов за запуск.
* `--retry-errors` сбрасывает `error` в `new` для повторной попытки.
